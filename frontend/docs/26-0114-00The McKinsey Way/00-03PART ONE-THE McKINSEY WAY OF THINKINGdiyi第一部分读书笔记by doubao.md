# 《麦肯锡式商业问题思考法（Part One）》学习型读书笔记
## 1️⃣ 整体一页图景
Part One 专门解决商业里模糊、复杂、信息不全的“大问题”，比如“怎么提高销量”“如何降本”“新业务要不要做”这类没明确方向的需求。它最适合用在没头绪、怕遗漏关键因素，或者需要说服他人认同方案的时候。和“凭经验想办法”最大的区别是，它不依赖直觉拍板，而是靠“事实+结构化拆解+假设驱动”，先搭好思考框架再填细节，既保证不混乱、不跑偏，又能让结论落地，而不是停留在“想法”层面。不管是职场新人还是资深管理者，遇到“不知道从哪下手”的问题时，这套方法都能帮你快速找到突破口，还能让方案更有说服力。

## 2️⃣ 核心知识要点清单
【要点 1】基于事实
这是什么？
思考和决策必须靠真实数据、案例等可验证的信息，而不是直觉或感觉。
解决什么问题？
避免凭经验判断的偏差，消除他人对结论的可信度质疑（比如新人说服老板、顾问说服客户）。
常见误解
收集的资料越多越好，把数据堆在一起就是“基于事实”。
正确用法提示
“只抓和假设相关的关键事实，够验证就停，不做无用功”。

【要点 2】MECE 原则
这是什么？
分类时做到“相互独立、完全穷尽”，不重叠、不遗漏。
解决什么问题？
思考混乱、有漏洞，比如拆分问题时重复讨论，或漏掉关键环节。
常见误解
为了分类而分类，纠结于“绝对完美的分类”。
正确用法提示
“先拆大类（2-5个），再补子项，实在归不进去就用‘其他议题’兜底”。

【要点 3】初步假设（IH）
这是什么？
项目初期基于有限信息，提出的“可能的解决方案”，相当于思考的路线图。
解决什么问题？
信息不全时无从下手，陷入“等所有数据再思考”的停滞。
常见误解
假设是最终答案，或者是拍脑袋的猜测。
正确用法提示
“先定大方向，用假设牵引找事实，错了就调整，不执着”。

【要点 4】议题树（Issue Tree）
这是什么？
把初步假设拆成一层一层的子议题，形成树状结构，让思考有层次。
解决什么问题？
假设太笼统，不知道该从哪验证，或思考发散没重点。
常见误解
把议题树做的太复杂，每个子项都想拆到最细。
正确用法提示
“先搭主干（对应初步假设的大类），再拆2-3层，够指导分析就停”。

【要点 5】80/20 法则
这是什么？
20%的关键因素能决定80%的结果，优先聚焦核心。
解决什么问题？
平均用力、资源分散，在次要问题上浪费时间。
常见误解
只找20%的点，完全忽略其他80%。
正确用法提示
“先抓核心驱动因素，集中资源解决，剩下的后续再优化”。

【要点 6】找到核心驱动因素
这是什么？
在所有影响问题的因素里，挑出最关键、最能改变结果的几个。
解决什么问题？
分不清主次，被无关因素干扰，导致分析低效。
常见误解
把“自己熟悉的因素”当成核心驱动。
正确用法提示
“用数据和事实验证，哪个因素影响最大，就聚焦哪个”。

【要点 7】契合客户现实
这是什么？
解决方案要适配客户/组织的能力、资源、政治环境，不能只追求理论最优。
解决什么问题？
方案太理想化，没人能执行，最终沦为“纸上谈兵”。
常见误解
“对的方案就该被执行”，忽略现实约束。
正确用法提示
“先看能不能落地，再谈好不好，不做‘空中楼阁’的方案”。

【要点 8】切勿大海捞针
这是什么？
不做无目的的分析，只收集和核心议题相关的信息。
解决什么问题？
陷入“数据堆砌”，做大量无用分析，浪费时间和精力。
常见误解
分析越全面越好，怕漏掉任何一个细节。
正确用法提示
“围绕议题树找信息，够验证假设就停，不做多余分析”。

【要点 9】摘取低垂的果实
这是什么？
问题解决过程中，先做容易实现、能快速见效果的事。
解决什么问题？
长期没成果，团队士气低，或客户失去耐心。
常见误解
只做简单的，忽略核心问题。
正确用法提示
“先拿小胜利，再攻硬骨头，兼顾效果和士气”。

【要点 10】电梯测试
这是什么？
能在30秒内清晰说明核心结论和价值。
解决什么问题？
结论太复杂，别人记不住，或说不清楚核心价值。
常见误解
把30秒的内容做得太简略，没说清关键收益。
正确用法提示
“先讲结论，再讲3个核心依据，最后说收益，简洁有力”。

## 3️⃣ 要点之间的关系图
“基于事实”和“初步假设”是整个流程的前置条件——先有假设（路线图），再用事实验证；MECE 原则是搭建“议题树”的核心规则，确保拆解不重不漏；“核心驱动因素”和“80/20 法则”是配合使用的，帮你从议题树中挑出优先分析的部分，避免平均用力；“切勿大海捞针”是校正规则，防止你在收集事实时跑偏；“摘取低垂的果实”是过程中的落地技巧，兼顾效率和士气；“契合客户现实”是最终的过滤规则，确保方案能执行；“电梯测试”是对结论的最终检验，保证别人能快速理解。

## 4️⃣ 假设性案例
案例：一家本地连锁咖啡店（3家门店），最近3个月日均客流量下滑15%，营收同步下滑12%，老板想“尽快提升客流量和营收”，但不知道问题出在哪，预算有限（每月最多能投入5000元优化），且不能闭店装修。

## 5️⃣ 用 Part One 的方法，把案例完整走一遍
### 第一步：原始问题（模糊/错误的）
“尽快提升客流量和营收”（太笼统，没有明确目标、时间、范围，无法落地）。

### 第二步：重写为“可解决的问题”
“未来3个月内，在每月优化预算≤5000元、不闭店装修的前提下，使3家门店日均客流量回升10%（从当前100人/天回到110人/天），营收同步增长12%（从当前8000元/天回到9000元/天）”（明确目标、时间、约束条件，可衡量、可落地）。

### 第三步：给出初步假设（IH）
咖啡店客流量和营收下滑，核心源于“产品吸引力不足、到店便利性不够、周边营销触达有限”，可通过“优化核心产品、提升到店体验、做社区精准营销”这三点，在约束条件内实现目标。

### 第四步：搭建 Issue Tree（文本树状结构）
```
未来3个月实现客流量回升10%、营收增长12%
├─ 优化核心产品（提升产品吸引力）
│  ├─ 现有爆款咖啡/点心满意度是否下降？（需验证）
│  ├─ 是否需要新增1-2款低成本新品？（假设）
│  └─ 产品定价是否合理（和周边竞品比）？（需验证）
├─ 提升到店便利性（降低到店门槛）
│  ├─ 门店营业时间是否匹配目标客群作息？（需验证）
│  ├─ 周边停车/公共交通是否方便？（需验证）
│  └─ 到店点单/取餐等待时间是否过长？（需验证）
└─ 做社区精准营销（扩大触达）
   ├─ 周边3公里内目标客群（上班族、居民）是否知道门店？（需验证）
   ├─ 有没有简单的会员/复购活动？（假设）
   └─ 社交媒体（小红书、社群）是否有基础宣传？（需验证）
```

### 第五步：区分假设和需验证的点
- 假设（无需先找事实，可直接设计方案）：新增1-2款低成本新品、推出简单会员复购活动；
- 需事实验证（必须找数据/调研确认）：现有产品满意度、定价合理性、营业时间匹配度、停车/交通便利性、等待时间、周边客群触达率、社交媒体宣传情况。

### 第六步：用 80/20 判断优先分析哪一块
核心驱动因素：产品吸引力（客户最关注，且调整成本低）、周边客群触达率（很多本地店下滑是因为“没人知道”），这两块能决定80%的结果，优先分析；
次要因素：停车/交通便利性（短期无法改变）、营业时间（调整空间小），后续再优化。

### 第七步：根据“客户/现实约束”修正结论
约束条件：每月预算≤5000元、不闭店装修；
修正方向：
1. 产品优化：不做复杂研发，新增1款低成本新品（比如季节限定饮品，原料成本低），优化现有爆款的口感（调整配方，无额外成本）；
2. 营销：不做付费广告，聚焦社区社群（建周边居民/上班族群，发优惠券）、小红书本地探店（找3-5个素人博主，费用控制在3000元内）；
3. 到店体验：不装修，只优化点单流程（比如提前在社群接龙点单，减少等待时间），无额外成本。

### 第八步：给出“当前可执行”的方案
1. 产品端（本月内完成）：优化现有2款爆款咖啡的口感（和供应商沟通调整配方），新增1款季节限定果咖（原料成本≤8元/杯，售价18元）；
2. 营销端（1-2个月完成）：① 建周边3公里内的居民/上班族社群，入群送5元优惠券，每周发1次新品/活动通知；② 找3个本地素人博主（粉丝5000-1万），每人支付1000元，到店拍摄探店视频，重点推爆款和新品；
3. 体验端（本月内完成）：推出“社群接龙点单”服务，每天早上9点前接龙，中午/下午分时段取餐，减少等待时间；
4. 验证：每周统计客流量和营收，根据数据调整新品口味或营销力度。

## 6️⃣ 最后一页：Part One 的「记忆版流程清单」
1. 看到模糊问题，先把它拆成“有目标、有时间、有约束”的可解决问题（比如“提升营收”→“3个月内，预算5000元，营收增长12%”）；
2. 基于现有信息，提一个“可能的解决方案”（初步假设），作为思考的路线图；
3. 用 MECE 原则搭议题树，把假设拆成一层一层的子议题，确保不重不漏；
4. 区分哪些是假设（可直接做）、哪些需要事实验证（找数据/调研），列好要验证的清单；
5. 用 80/20 法则挑出2-3个核心议题，优先分析，不平均用力；
6. 收集关键事实，验证或调整初步假设，不对就及时改；
7. 结合客户/现实约束（预算、能力等），修正方案，确保能落地；
8. 提炼核心结论和可执行动作，用电梯测试检验（30秒说清楚），然后推进。

# 第 1 步｜把“模糊问题”改写成「可解决问题」

### ❌ 原始问题（模糊 / 不可执行）

> doviai 要不要卖“设计判断力”？

这个问题 **不可解**，原因：

* 没时间
* 没对象
* 没成功标准
* 没约束条件

---

### ✅ 可解决问题（我先给你一个版本）

> **在不增加教师人力、不引入 1v1 服务的前提下，
> doviai 是否能通过“课程产品化”的方式，
> 在 6 个月内验证：
> 用户是否愿意为“设计决策能力提升的结果”付费？**

🔎 这里已经**隐含了 4 个约束**：

* 时间：6 个月
* 形式：课程产品（不是咨询）
* 成本：不加人
* 验证目标：是否愿意付费（不是口碑）

👉 **先别急着改**，你只需要回答一句：
**这个问题，是否是你现在“真的想解决的”？**
（是 / 否 + 一句原因）

> ⚠️ 你只要回答这一句，我们继续。

# 第 2 步｜提出一个「危险但可被推翻的 IH」

> 这是整套方法里**最重要的一步**。

### ✅ IH–0（我先给你一个“狠版”）

> **如果 doviai 把课程的最小单元，从“教你怎么做”，
> 改为“让你在关键节点必须做一次选择并被点评”，
> 那么即使不写“判断力”，
> 用户仍会愿意为这种训练付费。**

为什么这是一个 **合格 IH**：

* ✔ 有方向性（课程结构改变）
* ✔ 可被推翻（用户可能不买）
* ✔ 一旦成立，能直接指导产品设计
* ✔ 能砍掉大量无关讨论（比如工具、软件）

👉 **现在你只需要做一件事**：
**这条 IH，你是“基本认同”，还是“直觉反对”？**
（不用解释，只选一个）

# 第 3 步｜搭 Issue Tree（只保留 3 个一级分支）

> 原则：**只拆到“可以指导行动”，不追求完整**

```
IH 是否成立？
├─ A. 用户是否真的愿意为“被迫做选择 + 被纠错”付费？
├─ B. doviai 是否能持续提供“有价值的判断点评”？
└─ C. 这种训练是否能被用户感知为“真的有进步”？
```

这是一个 **非常标准、非常 McKinsey 的三分法**：

* A = 需求侧
* B = 供给侧
* C = 可验证性

👉 到这一步你**不用改树**，
你只要点头：
**这 3 个，是不是你现在最关心的“生死问题”？**

# 第 4 步｜区分：哪些是假设？哪些要验证？

### 🟡 目前只是“假设”的（可直接设计）

* 用“选择题 + 解释原因”作为课程作业形式
* 用“错误点评”而不是“示范教学”作为老师价值
* 用真实案例，而不是抽象原则

### 🔴 必须验证的（否则不能继续）

* 用户是否愿意公开暴露“我选错了”
* 用户是否觉得“点评”比“示范”更值钱
* 用户是否能在 2–3 次训练后，**自我感知到变化**

👉 记住：
**这些不是靠“感觉”判断的，而是后面要被实验验证的。**

---

# 第 5 步｜用 80/20 选“最先验证哪一块”

> 资源有限，只能先验证一件事。

### 🎯 核心 20%（最先验证）

> **用户是否愿意为“被纠错式训练”付费或持续参与**

原因：

* 如果不愿意，后面全没必要做
* 这是需求真假的分水岭

### ❌ 暂时不优先

* 品牌故事
* 体系完整性
* AI 辅助程度

👉 **这里你不用决定**，这是标准选择。

---

# 第 6 步｜收集“最低成本事实”来验证

> McKinsey 的核心不是“研究”，而是**便宜地验证**。

### 可执行验证方式（低成本）：

1. **前奏课实验**

   * 一节课
   * 一个真实案例
   * 3 个方案必须选 1 个
   * 必须写“为什么”

2. **点评方式 A/B**

   * A：老师示范正确解
   * B：老师只指出“你哪里危险”

3. **行为指标**

   * 是否反复看点评
   * 是否在下次作业中明显避开同类错误

👉 这些都是**事实，不是感受**。

---

# 第 7 步｜结合 doviai 的现实约束，修正结论

### 现实约束（我们必须承认）

* 你是核心供给者
* 精力有限
* 不能靠大量 1v1

### 因此修正后的策略是：

* **判断点评必须“结构化、可复用”**
* 课程不是无限扩展，而是**少而狠**
* 产品价值 ≠ 覆盖面，而是**纠错密度**

---

# 第 8 步｜给出「现在就能执行的版本」

### 🎯 当前可执行决策（不是最终版）

> **推出一门“设计决策前奏课”，
> 每一课只做一件事：
> 让学员在一个真实节点上做选择，
> 然后被指出“你这一步为什么危险”。**

成功与否的判断标准只有一个：

> **学员在第 3 次作业时，
> 明显减少“看起来很对但其实错”的选择。**
