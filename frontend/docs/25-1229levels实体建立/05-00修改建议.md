## 四、⚠️ 你现在**必须修的 3 个问题**

### ❌ 问题 1：正则范围 **过大且不稳定**

```js
(?:.|\n){0,50}
```

#### 问题本质

* 50 字符的窗口：

  * **太宽**
  * 会跨句
  * 会跨列表
  * 会跨 HTML 标签

这会导致：

```txt
进阶能力说明……
（中间一大段内容）
本课程 Level 说明
```

👉 **被误判为“进阶 + Level”**

这是**迟早会发生的误杀**。

---

#### ✅ 必须修改为（建议）

把判断压缩到**同一句 / 同行 / 短窗口**：

```js
const levelTranslationRegex = new RegExp(
  `(${chineseLevelTranslations.join('|')})\\s*(阶段|级别|等级)|` +
  `(阶段|级别|等级)\\s*(${chineseLevelTranslations.join('|')})`,
  'g'
);
```

👉 **只允许紧邻关系**
👉 不跨行
👉 不跨段

---

### ❌ 问题 2：没有区分「实体引用位置」与「普通正文」

目前规则是：

> 只要命中 → ERROR

但你真正的**语义红线**是：

> ❌ Course / Level / Program 正文里 **用中文替代 Level 实体名**

而不是：

> ❌ 任何地方出现「进阶阶段」

#### 举例（你未来一定会写的）：

```md
### 学习过程分为三个阶段
- 入门阶段
- 进阶阶段
- 深度实践阶段
```

⚠️ **这里的“进阶阶段”不是 Level 实体**
⚠️ 但当前规则会直接 ERROR

---

#### ✅ 正确做法（最低限）

增加一个 **实体引用触发条件**（必须二选一）：

* 同时出现：

  * `Intermediate` / `Beginner` / `Advanced` 的英文之一
    **或**
  * `/levels/`
    **或**
  * `educationalLevel`

示例补丁思路（不是完整代码）：

```js
const ENTITY_ANCHOR = /(Intermediate|Beginner|Advanced|\/levels\/|educationalLevel)/;

if (!ENTITY_ANCHOR.test(content)) {
  return errors;
}
```

👉 **没有实体锚点，就不认为这是 AEO 层违规**

---

### ❌ 问题 3：index.js 的使用方式 **与你之前设计的不一致**

Trae 的 `index.js` 是：

```bash

```

但你之前规划的是：

```bash

```

现在的行为是：

* ❌ 不能递归目录
* ❌ CI 用起来会很麻烦
* ❌ 以后加规则会受限

这不是“错”，但**与你之前的 lint 设计目标冲突**。

---

#### ✅ 修正建议（你现在就该做）

在 `index.js` 中加一句：

* 如果参数是目录 → 递归扫描

否则你以后每加一个文件类型都会痛一次。
