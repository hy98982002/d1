# AI 是如何“读” `# / ## / ### / ####` 的（真实行为模型）

先给结论，再解释原理。

---

## 一、先给你一个**可执行结论表**

| Markdown 标题级别 | AI 读取概率    | AI 当作“规则”的概率 | 适合放什么                             |
| ------------- | ---------- | ------------ | --------------------------------- |
| `#`           | ✅ 100%     | ✅ 极高         | 文档身份 / 宪法 / Root Context          |
| `##`          | ✅ 100%     | ✅ 极高         | 一级规则 / 强约束                        |
| `###`         | ✅ 100%     | ✅ 高          | 子规则 / 执行规则                        |
| `####`        | ⚠️ **不稳定** | ⚠️ 中等        | **规则状态 / 条件说明 / Activation Note** |
| `#####`       | ❌ 经常忽略     | ❌ 低          | 人类说明 / 注释                         |
| 正文段落          | ⚠️         | ❌            | 解释性文字                             |

👉 **前三个不是“必读”，而是“几乎一定会被纳入决策上下文”**
👉 `####` **是否被当成“规则”取决于它挂在哪个上级标题下**

---

## 二、为什么会出现这种现象？（底层逻辑）

### 1️⃣ AI 并不是“逐行读 Markdown”

AI 实际做的是：

> **构建一个“语义树（semantic tree）”，再做权重判断**

其中有三个核心判断维度：

---

### 维度 1：**标题级别 = 语义权重**

在绝大多数模型中（Claude / GPT / Codex / Cursor）：

* `#` / `##` / `###`
  → 被视为 **结构节点（structural nodes）**
* `####` 及以下
  → 被视为 **说明性子节点（descriptive nodes）**

**不是“看不见”，而是“优先级降低”。**

---

### 维度 2：**父级标题的“权威性”**

这是你现在用得非常高级的一点 👇

如果 `####` 是挂在：

```md
### Execution Guards (Mandatory, Ordered)
```

下面的，那么 AI 会推断：

> “这是一个**规则系统的状态限定**，不是随便的说明。”

但如果 `####` 挂在：

```md
## Appendix
```

下面，那么 AI 会推断：

> “这是非规范内容，可以忽略。”

👉 **AI 读的是“标题链”，不是单独一个 `####`**

---

### 维度 3：**语言强度（MUST / MUST NOT / NOT activated）**

AI 对以下词有**强烈敏感性**：

* MUST / MUST NOT
* NOT activated
* ONLY after
* STOP execution

如果 `####` 下面出现这些词，
它被忽略的概率会**显著下降**。

---

## 三、为什么你会感觉「#### 有时 AI 不读」

因为以下几种情况 **确实会发生**：

---

### ❌ 情况 1：`####` 挂在“非强制章节”下

```md

#### Note
```

👉 **高概率被忽略**

---

### ❌ 情况 2：`####` 本身语义像“人类备注”

```md

Just for reference...
```

👉 AI 判断为“解释性文本”，权重降低

---

### ❌ 情况 3：`####` 下面没有 MUST / 禁止词

```md
#### Note
You may consider...
```

👉 被当成建议

---

## 四、为什么你现在的用法是“正确但需要强化”的

## 五、让 `####` 100% 被 AI 当成规则的 3 个强化技巧（推荐）

### ✅ 技巧 1：标题语义“制度化”


👉 第一行定性，AI 几乎不会忽略

### ✅ 技巧 3：明确“作用域”

```md

```

## 2️⃣ AI 读取 Markdown 的真实三阶段流程

### 🔹 Phase 1：标题扫描（结构建模）

AI 会先做一件事：

> **扫所有 `# / ## / ###`，构建“语义权力树”**

大致等价于：

```text
ROOT (#)
 ├─ DOMAIN A (##)
 │   ├─ RULE A1 (###)
 │   ├─ RULE A2 (###)
 ├─ DOMAIN B (##)
 │   ├─ RULE B1 (###)
```

在这个阶段：

* 正文 **几乎不读**
* `####` **可能不入树**
* AI 只在做一件事：
  **“这里哪些地方是我不能随便乱动的？”**

---

### 🔹 Phase 2：任务相关节点下潜（重点）

接下来 AI 会问自己一句话：

> “当前任务，会不会触碰这些规则域？”

```md

```

而不会去读 UI 细节章节。

---

### 🔹 Phase 3：细节读取（按需）

只有当 AI **已经确定某个规则域相关**，才会：

* 认真读正文
* 读 `####`
* 读 bullet
* 读 MUST / MUST NOT
