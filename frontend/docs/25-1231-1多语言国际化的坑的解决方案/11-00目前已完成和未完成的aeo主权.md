从 `/CLAUDE.md` 和 `/frontend/CLAUDE.md` 中，我可以总结出以下核心 AEO 架构哲学：

### 1. 分层文档治理体系
- `/CLAUDE.md` 是最高级宪法，仅包含不可违背的长期规则、AEO/语义/架构红线
- `/frontend/CLAUDE.md` 是前端专用执行细则，回答"在前端具体怎么做"
- 其他文档如 CHANGELOG.md、docs/ 等各有明确职责边界

### 2. 实体主权与语义边界
- **Program**: 是"教学结构顺序"的唯一主权实体，负责定义课程的强依赖与顺序
- **Course**: 独立的教学单元，不得定义学习顺序或学习路径
- **Path**: 只负责"Skill 之间的推荐学习顺序"，不替代 Program 的结构主权
- **Topic**: 仅作为主题聚合，不得表现为 Program/Path
- **Levels**: 学习阶段定义，不承载具体教学内容

### 3. 核心原则
- **语义身份隔离（AEO 第一原则）**: 参与 @id 的标识符不得参与导航、本地化或排名信号
- **单一职责原则**: 每个页面类型必须遵循单一、不重叠的语义职责
- **唯一命名源**: StageKey 枚举（beginner | intermediate | advanced）必须在所有位置完全一致
- **Slug 稳定性原则**: Slug 是语义锚点，必须长期稳定

### 4. 实体关系规则
- **强制关系**: Program ↔ Course 使用 hasPart/isPartOf
- **禁止关系**: Topic 不得使用 hasPart，Course 不得在 Program 上下文外定义位置
