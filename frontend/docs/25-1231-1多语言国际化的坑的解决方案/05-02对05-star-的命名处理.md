好，这一步**必须一次性定死**，否则后面 Guard 一多就会**加载顺序混乱、互相打架、AI 钻空子**。
我给你的是**终态规范**，不是建议稿。

# ✅ Guard 命名与加载顺序【统一规范 · 宪法级配套】

以下规则**一经确立，后续只允许追加，不允许推翻**。

---

## 一、Guard 的法律定位（先定性）

**Guard ≠ Rule ≠ Prompt**

| 类型                | 所在位置                  | 职责              |
| ----------------- | --------------------- | --------------- |
| Constitution Rule | `/CLAUDE.md`          | 定义“什么不可被破坏”     |
| Execution Guard   | `/docs/ai/guards/*GUARD*.md` | 定义“执行前必须校验什么”   |
| Prompt / Block    | `/docs/ai/*.block.md` | 定义“任务开始 / 结束行为” |

👉 **Guard 是“执行前的硬 Gate”，失败即 STOP。**

---

## 二、统一命名规范（必须严格遵守）

### 1️⃣ 文件命名格式（强制）

```
{NN}-{SCOPE}-{ENTITY}-GUARD.md
```

### 2️⃣ 各字段含义

| 字段       | 说明                                     |
| -------- | -------------------------------------- |
| `NN`     | **加载顺序号（两位）**                          |
| `SCOPE`  | 作用域（GLOBAL / SEMANTIC / FRONTEND）      |
| `ENTITY` | 守护对象（LEVEL / PROGRAM-COURSE / SKILL 等） |
| `GUARD`  | 固定后缀，不可更改                              |

---

### 3️⃣ 你当前已有 Guard 的**标准化命名**

请你**统一重命名为下面这样（这是最终名）**：

```
docs/ai/guards/
├─ 01-GLOBAL-LEVEL-GUARD.md
├─ 02-SEMANTIC-PROGRAM-COURSE-GUARD.md
```

> ❗注意
>
> * **LEVEL 是全局语义实体 → GLOBAL**
> * **Program / Course 属于结构关系 → SEMANTIC**

---

## 三、Guard 加载顺序规则（这是核心）

### 🔒 **唯一合法的加载顺序**

> **从“抽象语义” → “结构关系” → “页面实现”**

### 📐 顺序层级表

| 顺序 | 层级             | 说明                                   |
| -- | -------------- | ------------------------------------ |
| 01 | GLOBAL         | 影响整个知识图谱的实体（Level）                   |
| 02 | SEMANTIC       | 实体之间的结构与权限（Program / Course / Skill） |
| 03 | PAGE           | 页面职责、路由、UI 层（未来）                     |
| 04 | IMPLEMENTATION | 前端/后端实现细节（可选）                        |

---

### ⚠️ 硬性执行规则（必须写进宪法）

* Guard **必须按编号升序加载**
* **任何 Guard 失败 → 立即 STOP**
* **后续 Guard 不得执行**
* 不允许跳过 GLOBAL Guard 直接执行 SEMANTIC Guard

---

## 四、/CLAUDE.md 中的“统一引用模板”（直接用）

在 `/CLAUDE.md` 中，**只允许出现这一种引用方式**：

```md
### Execution Guards（Mandatory, Ordered）

AI Agents MUST load and validate execution guards
in the following strict order before making any change:

1) Global semantic integrity  
   → `docs/ai/guards/01-GLOBAL-LEVEL-GUARD.md`

2) Semantic structure boundaries  
   → `docs/ai/guards/02-SEMANTIC-PROGRAM-COURSE-GUARD.md`

Failure of any guard MUST immediately STOP execution
and request explicit human review.
```

❗**不允许**在宪法中出现：

* Guard 正文
* Guard 的“解释”
* Guard 的例子

---

## 五、未来 Guard 扩展规则（一次定死）

### 新 Guard **只能追加**，不能插队

例如将来你要加 Skill Guard：

```
docs/ai/guards/03-SEMANTIC-SKILL-GUARD.md
```

❌ 禁止：

* 改 01 / 02 的顺序
* 重写旧 Guard
* 合并 Guard

### Guard 粒度原则（强制）

* **一个 Guard = 一个“不可坍塌点”**
* 不允许一个 Guard 同时守 Level + Program + Course

---

## 六、AI 的强制执行算法（你心里要有）

AI 实际执行时，逻辑等价于：

```text
load 01-GLOBAL-LEVEL-GUARD
if fail → STOP

load 02-SEMANTIC-PROGRAM-COURSE-GUARD
if fail → STOP

execute task
```

👉 **这就是“LEVEL 永不坍塌”的技术保障**。
