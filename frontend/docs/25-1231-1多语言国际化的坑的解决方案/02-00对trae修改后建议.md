# 二、必须修的 3 个问题（重点）

下面这 3 个点，是**结构性错误**，不是措辞问题。

---

## ❌ 问题 1：StageKey（UI 状态）混进了 Entity 规则（严重）

### 现在的结构（有问题）：

```md
### 2) Level / Program / Course Page–Entity Separation

#### 阶段管理
- 学习阶段使用 StageKey 枚举
- assertStageKey 校验
```

### 为什么这是错的（说清楚）：

* `StageKey` = **UI / 路由 / 状态管理概念**
* `Level entity` = **语义实体（AEO / JSON-LD）**

它们**名字像，但不是一个层级的东西**。

> 你现在等于在对 AI 说：
> **“UI 的 stage 和语义的 Level 是同一层级”**

这在半年后一定会导致：

* JSON-LD 生成器误用 StageKey
* AI 把 `?stage=intermediate` 当 entity
* lint 规则开始互相打架

### ✅ 正确修法（必须做）

**把 StageKey 相关内容整体移走**：

```md
## UI State & Routing Rules
```

或放回原本的「数据与状态管理」章节。

在 AEO 章里，只允许出现：

* Level entity
* Program entity
* Course entity

---

## ❌ 问题 2：Slug 规则被错误提升为 AEO 规则（中度）

你现在写的是：

```md
### 2) Level / Program / Course Page–Entity Separation
#### Slug 管理
```

### 问题在哪？

* Slug 是 **页面工程规则**
* AEO 关心的是 **entity @id**
* Slug ≠ entity identity（你自己前面已经立过这条硬规则）

这会产生**自相矛盾的阅读路径**。

### ✅ 正确修法（推荐）

把 Slug 规则拆出去：

```md
## Page URL & Slug Rules (Frontend)
```

然后在 AEO 章里 **只保留一句引用**：

```md
Page URLs and slugs are presentation-layer concerns and MUST NOT be used as entity identifiers.
```

---

## ❌ 问题 3：Level 实体名不可翻译是“三级标题”，级别不够（必须上提）

现在是：

```md
### Level 实体名不可翻译（实体引用时必须英文）
```

### 为什么级别不够？

这条规则：

* 会进入 aeo-lint
* 会 CI 拦截
* 会影响所有语言站
* 会影响 Course / Program / Level 三类页面

👉 **这是“实体身份规则”，不是补充说明**

### ✅ 正确修法（必须）

把它并入：

```md
### 1) Entity Identity & Canonical IDs
```

并作为 **编号规则**，例如：

```md
- Rule 1.1: Canonical @id must be language-agnostic
- Rule 1.2: Level entity names MUST remain in English
```

这样 **lint / 人 / AI 的权重判断才一致**。
