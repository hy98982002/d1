你将基于我提供的「10* AEO 规则补充文档」，完成一次严格的工程级拆解与落地。

这是一个【架构判断任务】，不是简单编码任务。

你的任务分为四个阶段，必须按顺序完成，不得跳步。

--------------------------------
阶段 1：规则拆解（强制）
--------------------------------

请通读 10* 文档中的所有规则与说明，并将每一条规则【逐条】拆分并归类为以下三类之一：

1) Lint 级规则
   - 可以被确定性、无歧义、无需语义推断地自动检测
   - 违反时应视为 ERROR，可直接阻断 CI
   - 适合实现为 aeo-lint 的 rules/* 文件

2) 宪法级规则
   - 属于跨前后端、跨模块、长期不变的最高级约束
   - 不依赖具体实现细节
   - 应写入根目录 /CLAUDE.md
   - 不应写入 frontend/CLAUDE.md 或 lint

3) 文档级规则
   - 用于解释、背景说明、设计原因、经验总结、未来风险
   - 不能被机器可靠检测
   - 只能写入说明文档（README / docs）
   - 严禁实现为 lint

你必须输出一个清单，格式如下：

- 规则原文：
- 分类结果：Lint / 宪法 / 文档
- 分类理由（必须明确说明“为什么不能/可以 lint”）

--------------------------------
阶段 2：Lint 级规则实现（仅限此类）
--------------------------------

【只】对被你归类为「Lint 级」的规则执行以下操作：

- 在 tools/aeo-lint/rules/ 中新增或修改对应规则文件
- 每条规则必须：
  - 确定性（无 NLP、无推断）
  - 可读错误信息
  - 明确 ERROR 等级
- 更新 aeo-lint README / 说明文档，列出新增规则

严禁将「宪法级」或「文档级」规则强行实现为 lint。

--------------------------------
阶段 3：规则对齐检查（强制）
--------------------------------

在完成后，请自检并明确回答：

- 是否有任何 lint 规则无法在 frontend/CLAUDE.md 中找到对应的“文字硬规则”
- 是否有任何规则被错误地放入 lint（但实际上需要人类判断）

如有，必须回滚并修正。

--------------------------------
阶段 4：结果汇总
--------------------------------

请输出：

1) 三类规则的完整清单
2) 新增 / 修改的 lint 规则文件列表
3) 是否有规则被明确拒绝进入 lint（以及原因）

注意：
- 不要替我“简化规则”
- 不要为了“覆盖更多情况”牺牲确定性
- aeo-lint 是结构防火墙，不是语义分析器
