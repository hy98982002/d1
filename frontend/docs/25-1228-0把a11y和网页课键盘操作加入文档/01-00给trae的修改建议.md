# 1️⃣ 对 00* 无障碍规范的评测（是否需要补充）

你当前的 00* 文件符合：

* WCAG 2.1 AA
* 现代前端可访问性工程实践
* Vue / SPA 场景下的现实可行性

### ✅ 已经覆盖得很好的部分（无需改）

以下内容**已经是“工业级标准答案”**，不用动：

* WCAG 2.1 AA 作为目标等级
* 语义化 HTML（header / nav / main / footer）
* 图像 `alt` / 装饰图空 alt

  * Tab 顺序
  * Enter / Space 激活

这些内容**非常适合进入 AI 行为规范**，让 AI 默认执行。

## ⚠️ 必须补充的 3 个“宪法级缺口”（重点）

不是“有没有更好”，而是 **现在缺了这 3 条会出事故**。

---

### 🔴 补充点 1：禁止“伪按钮 / 伪链接”（极重要）

你现在的规范**教了如何用 `tabindex` 修补 div**，
但**没有禁止错误模式本身**。

#### 必须新增一条**硬禁令**：

> ❌ **禁止使用 `div` / `span` 伪装 button / link**
> 除非该元素：
>
> * 拥有 `role`
> * 完整键盘行为（Enter / Space）
> * 完整 aria 状态
>   否则一律视为 **A11y 违规**

这是无障碍领域的**第一大真实事故源**。

---

### 🔴 补充点 2：`:focus-visible` 强制规则（AI 常犯错）

现在很多 AI 会做这种事（这是**真实风险**）：

```css
:focus {
  outline: none;
}
```

但你当前规范**没有明确禁止**。

#### 必须加一条宪法级规则：

> * ❌ 禁止移除 focus outline
> * ✅ 只能使用 `:focus-visible` 自定义
> * ❌ 不得仅依赖 hover 表现交互状态

这是**键盘用户的生命线**。

---

### 🔴 补充点 3：动画 / Motion 对 a11y 的约束（与你现有动画规则冲突）

你之前已经有一套 **Apple HIG 动画规则**，但：

* a11y 规范里 **没有处理“减少动态”**
* 这在 WCAG 2.1 是明确要求

#### 必须补充：

```css
@media (prefers-reduced-motion: reduce) {
  * {
    animation: none !important;
    transition: none !important;
  }
}
```

否则：
👉 **动画规则与无障碍规则发生隐性冲突**（这是宪法级问题）

---

## 🧠 评测总结（给你一句“裁决式结论”）

> **00*** 文件本身是「合格的工程规范」，
> 但如果要升级为「AI 自动执行级规则」，
> **必须补上：交互语义禁止项 / focus-visible / reduced-motion 三条红线**。
