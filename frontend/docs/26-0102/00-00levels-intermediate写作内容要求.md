在levels/Intermediate会有不同专业技能的课，在解释阶段的时候，是每个技能课分开解释？



不分开。**在 `/levels/intermediate` 这个层级，绝对不要按“具体技能课”逐一解释。**
这是一个**结构性硬约束**，不是文案偏好问题。

我分三步把**为什么不分开、应该怎么写、哪些地方才该分开**讲清楚。

------

## 一、先给结论（可直接执行）

> **Level 页面只解释“阶段能力”，不解释“技能细节”。**
>
> `/levels/intermediate` 的解释对象是：
> **“什么样的人处在 Intermediate 阶段”**
> 而不是：
> **“Intermediate 里有哪些具体技能课”**

所以答案是：

- ❌ **不是**：UI 设计一段、Logo 设计一段、前端一段……
- ✅ **而是**：一套**跨技能通用的阶段能力定义**

------

## 二、为什么“按技能分开解释”是一个必踩的大坑

### 1️⃣ 从 AEO / 实体权威角度（致命）

在知识图谱里：

- **Intermediate 是一个实体**
- **UI / Logo / Frontend 是另一组实体**

如果你在 `/levels/intermediate` 里这样写：

> Intermediate · UI 设计是……
> Intermediate · Logo 设计是……
> Intermediate · 前端是……

你等于在暗示：

> **Intermediate 的定义会因技能而改变**

这在 AEO 里是**结构性错误**：

- 一个概念（Intermediate）
- 出现了多个解释源
- 权威被拆碎

👉 结果：
**搜索引擎无法确定“Intermediate 到底是什么”**

------

### 2️⃣ 从你自己的 Guard 规则看（直接违规）

回顾你已经写进“宪法级 Guard”的一条：

> **Level pages define difficulty concepts, NOT course details**

如果你按技能拆解释：

- UI / Logo / 前端
  → 都是 **course / skill 维度**

那就已经越权了。

------

### 3️⃣ 从未来扩展角度（会逼你返工）

今天你可能只有：

- UI
- Logo
- Photoshop

半年后你一定会有：

- AI UX
- Motion
- Web
- Data Visualization
- 甚至非设计技能

如果 Level 页按技能写：

- 每加一个技能
- 就要重写 Level 定义
- Level 页面永远不稳定

👉 这和 **“Level 是稳定抽象实体”** 的目标正好相反。

------

## 三、那 `/levels/intermediate` 到底应该怎么写？（标准答案）

### 正确写法：**“能力维度”，而不是“技能维度”**

你应该解释的是 **跨技能的通用能力门槛**，例如：

### ✅ 可以写的内容（示例结构）

#### 1️⃣ Intermediate 是什么（抽象定义）

> Intermediate 阶段代表学习者已经脱离“工具认知”，
> 开始具备**独立完成中等复杂任务的能力**。

#### 2️⃣ 进入该阶段的前置能力（不点名具体技能）

- 能理解并执行明确任务目标
- 能使用核心工具完成完整流程
- 不再依赖逐步演示
- 能判断结果是否“合格”

⚠️ 注意：
这里**不出现 UI / Logo / Frontend 等词**

------

#### 3️⃣ 该阶段的通用能力特征（核心）

- 从“学怎么做” → “知道为什么这样做”
- 能在约束条件下完成任务
- 开始接触真实场景与变体
- 可以复盘自己的结果

这是 **Level 的真正价值**。

------

#### 4️⃣ 再给一个「技能无关」的能力映射（可选但很强）

你可以用这种方式（非常推荐）：

> 在 Intermediate 阶段，无论学习的是哪种专业技能，
> 学员通常都会经历以下变化：

- 操作熟练度 ↑
- 判断能力 ↑
- 错误自修能力 ↑
- 对结果质量的自我评估 ↑

👉 这是 **跨技能稳定特征**。

------

## 四、那“不同专业技能”放在哪里解释？（关键分工）

### ✔ 正确的位置分布

| 内容                                        | 应该在哪                 |
| ------------------------------------------- | ------------------------ |
| UI / Logo / Frontend 在 Intermediate 学什么 | **Course 页面**          |
| 某一专业的进阶路径                          | **Program 页面**         |
| Intermediate 阶段意味着什么                 | **Level 页面**           |
| “这个技能在 Intermediate 的要求”            | **Program / Guide 页面** |

### ❌ 错误做法

- 在 Level 页面拆技能解释
- 在 Course 页面解释 Intermediate 的定义
- 在 Program 页面重新定义 Level 含义

# `/levels/intermediate` 标准内容骨架（AEO / LRMI 稳定版）

------

## H1：Intermediate（进阶阶段）

> 一句话定义这个阶段的**本质变化**
> （从“新手”到“可独立完成任务者”的转折）

------

## 一、Intermediate 是什么（概念定义 · 必须有）

**目的**：成为该 Level 的“语义权威解释源”

> Intermediate 阶段代表学习者已经完成基础入门，
> 不再依赖逐步示范，
> 开始具备在真实或近真实场景中**独立完成中等复杂任务**的能力。

⚠️ 规则：

- 不出现任何具体技能名称
- 不出现课程名
- 不出现工具名（如 PS / Figma / Vue）

------

## 二、适合什么样的学习者（Who）

**目的**：帮助用户和搜索引擎判断“我是不是这个阶段的人”

可以用 checklist 形式：

- 已完成至少一个完整学习闭环
- 能在明确目标下独立执行任务
- 理解基本概念，而不只是模仿操作
- 能识别结果是否达标

👉 全部是**状态描述**，不是技能描述。

------

## 三、进入该阶段的前置能力（Prerequisites）

**目的**：定义进入门槛，而不是教学内容

- 对所学领域的基本概念有清晰认知
- 能使用核心工具完成完整流程
- 能理解常见错误及其原因
- 不再需要逐行 / 逐步教学

⚠️ 不要写“会 UI / 会 Logo / 会前端”

------

## 四、该阶段的核心能力特征（最重要的一节）

**这是 Level 页的“核心价值区”**

可以用 3–5 条高度抽象、跨技能成立的能力描述：

- 从“照着做”转向“理解为什么这样做”
- 能在约束条件下完成任务（时间 / 需求 / 规则）
- 能根据反馈调整方案
- 开始建立质量判断标准
- 能复盘并改进自己的结果

👉 这一节**越抽象越好，只要真实**。

------

## 五、Intermediate 阶段的学习重点（不等于课程内容）

**目的**：解释“学习方式的变化”，而不是“学什么技能”

示例结构（你自行填）：

- 学习目标：从掌握操作 → 提升完成度
- 学习方式：从跟随演示 → 任务驱动
- 评估标准：从“做出来” → “是否可用 / 合格”

⚠️ 不出现任何课程、章节、工具。

------

## 六、在不同专业中，Intermediate 的表现形式（可选但推荐）

⚠️ 注意：**这里不是拆技能解释，而是强调“表现形式不同，但阶段本质相同”**

推荐写法：

> 在不同专业技能中，
> Intermediate 阶段的具体表现可能不同，
> 但其核心能力特征是一致的，例如：

- 能独立完成一次完整交付
- 能在已有规则下做出选择
- 能解释自己的设计 / 实现逻辑

这里**仍然不点名具体技能**。

------

## 七、你在这个阶段能做什么（Outcome）

**目的**：给用户一个“阶段完成后的心理锚点”

- 能独立完成中等复杂度任务
- 能开始参与真实或模拟项目
- 能理解并执行专业反馈
- 为更高阶训练打下基础

这是**阶段 Outcome，不是课程 Outcome**。

------

## 八、该阶段包含的课程（聚合区 · 低权重）

> **属于 Intermediate 阶段的课程**
