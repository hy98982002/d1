# 《Engaged》第5章读书笔记 + 在线教育平台应用分析
## 一、本章核心结构（行为诊断视角）
### 1. 本章核心问题
为什么用户“想做却没做”？真正阻碍目标行为发生的，不是缺乏动机，而是未被识别和解决的“能力障碍”。

### 2. 什么是“能力障碍”
定义：任何限制人们执行目标行为的因素，既可能与产品本身、使用环境相关，也可能源于用户自身。
强调：很多本应推动行为改变的产品失败，并非用户不想做，而是设计师未理解并解决行为背后的能力阻碍——专家容易陷入“知识诅咒”，忘记初学者的能力边界。

### 3. 行为改变轮盘与COM-B模型
COM-B模型是诊断能力障碍的核心框架，行为（B）的发生，依赖能力（C）、机会（O）、动机（M）三者的共同作用，任一要素不足都会导致行为失败。

| 要素 | 含义 |
|------|------|
| C – 能力 | 执行行为所需的生理与心理能力 |
| O – 机会 | 支持或阻碍行为的物理与社会环境 |
| M – 动机 | 驱动行为的反思性目标与自动性倾向 |

### 4. 能力（Capability）障碍类型
| 类型 | 例子 |
|------|------|
| 知识缺口 | 不知道“提交作品反馈”的具体流程 |
| 技能不足 | 懂UI设计理论，但不会操作Figma完成项目 |
| 时间不足 | 单次项目练习需3小时，远超用户碎片时间 |
| 注意力不足 | 学习环境嘈杂，或产品有过多无关功能分散注意力 |
| 情绪状态 | 因多次修改作品无果而产生焦虑，难以继续 |
| 资源工具不足 | 没有高性能电脑运行设计软件，或无法访问付费素材库 |

### 5. 机会（Opportunity）障碍
| 类型 | 含义 |
|------|------|
| 物理机会 | 学习环境无安静空间、网络不稳定，或设备无法支持设计软件运行 |
| 社会机会 | 身边无共同学习的同伴、缺乏老师及时指导，或家人不支持占用时间学习 |

### 6. 动机（Motivation）障碍（COM-B视角）
| 类型 | 含义 |
|------|------|
| 反思性动机 | 虽想“学会UI设计找工作”，但未明确与当前练习的关联 |
| 自动动机 | 习惯拖延、对重复的基础练习感到枯燥，或受“设计很难”的文化认知影响 |

### 7. 研究的真正目标
调研的核心不是“泛泛了解用户”，而是精准“找出行为障碍清单”——明确哪些因素正在阻止用户执行目标行为，为后续设计解决方案提供依据。

### 8. 数据网格（诊断矩阵）
用于系统组织调研收集的障碍信息，是行为设计的直接输入数据：

| 障碍类型 | 证据（用户反馈/观察结果） | 重要性评分（1-3分） |
|----------|--------------------------|----------------------|
| 技能不足（能力） | 30%学员反映“不知道如何将理论转化为项目实操” | 3 |
| 缺乏指导（机会） | 学员反馈“提交作品后3天无回应，失去动力” | 2 |

### 9. 本章一句话核心总结
像侦探一样，用COM-B模型拆解用户“想做却没做”的根本原因，通过针对性研究找出能力、机会、动机层面的障碍清单，才能为后续设计有效的行为支持方案奠定基础。

## 二、在线教育平台虚拟案例应用分析
### 目标产品
“UI Master”——帮助用户坚持完成UI设计学习路径，核心目标是让学员“每周完成2次项目练习并提交作品反馈”。

### 1. 目标行为
- 每周固定2次、每次1.5小时的UI项目实操练习
- 练习完成后48小时内提交作品，接收老师或同伴反馈

### 2. 学员“明明想学却没坚持”的COM-B障碍分类
| 类别 | 在线教育中的障碍 |
|------|------------------|
| 能力 | 1. 技能不足：会看设计教程，但不会独立完成项目；2. 时间不足：单次练习需3小时，用户仅能抽出碎片时间；3. 资源不足：部分学员无高性能电脑运行设计软件 |
| 机会 | 1. 物理机会：无安静学习空间、网络卡顿导致设计文件保存失败；2. 社会机会：缺乏同伴监督，老师反馈延迟超过48小时 |
| 动机 | 1. 反思性动机：不清楚当前练习与“就业所需技能”的关联；2. 自动动机：重复练习枯燥，无即时成就感，容易拖延 |

### 3. 一个“错误判断”
平台初期认为学员“没坚持”是“懒”（动机问题），因此增加了“每日打卡提醒”功能，但效果甚微。后续调研发现，核心障碍是“能力问题”——60%学员卡在“不会将教程内容转化为实操项目”，不知道从何下手，而非不愿做。

### 4. 如何通过调研发现这些障碍
- 观察：录制学员使用平台的过程，发现多数人在“新建项目”步骤停留超过10分钟，反复翻看教程却不操作；
- 访谈：询问学员“最想放弃的瞬间是什么时候”，收集到“不知道怎么开始设计”“反馈太慢没动力”等关键信息；
- 文献：查阅在线技能学习坚持率相关研究，发现“实操指导不足”“反馈延迟”是核心障碍；
- 行为日志：分析平台数据，发现学员登录后未完成练习的比例中，70%是打开项目页面后未进行任何操作就退出。

### 5. 数据网格在教育产品中的应用
| 障碍 | 证据 | 影响评分（1-3分） |
|------|------|----------------------|
| 实操启动困难（能力） | 70%未完成练习的学员，在“新建项目”步骤停留超10分钟无操作；访谈中80%学员提及“不知道从何开始设计” | 3 |
| 反馈延迟（机会） | 学员平均等待反馈时间为48.5小时，25%学员因反馈慢而停止提交作品 | 2 |
| 练习耗时过长（能力） | 65%学员反馈“单次练习需3小时，没时间完成” | 3 |
| 练习枯燥（动机） | 40%学员反映“重复的基础练习没意思，缺乏成就感” | 1 |

### 最终启发
在线教育产品要提升用户行为坚持率，核心不是“催用户学习”，而是像侦探一样用COM-B模型精准诊断“为什么学不下去”的能力、机会、动机障碍，再针对性提供解决方案——比如将长练习拆分为碎片任务、提供项目实操模板降低启动难度、缩短反馈周期等，让用户“能做、易做、愿意做”。

# 二、升华性总结（大师级层）

现在进入真正升华。

---

## 🎯 第一层升华：第5章不是“找问题”

而是：

> **建立“行为失败因果模型”**

COM-B 不是分类工具。
它是：

> **行为发生的必要条件系统**

行为是一个方程：

```
B = f(C, O, M)
```

任何一项下降，行为概率下降。

---

## 🎯 第二层升华：能力障碍的真正本质

能力不是“你会不会”。

能力是：

> **行为的“可执行性阈值”是否被满足**

这就像软件的系统要求：

| 行为     | 最低配置                |
| ------ | ------------------- |
| UI项目练习 | 技能 + 时间 + 情绪稳定 + 工具 |

低于阈值 → 行为无法运行。

这就是：

> 行为的“运行环境”。

---

## 🎯 第三层升华：障碍之间是连锁反应

最深层思想：

> **能力、机会、动机相互影响**

例如：

```
环境嘈杂（O） → 注意力下降（C） → 挫败感（M） → 放弃
```

所以行为失败不是单点，而是：

> **系统性失效**

---

### 对在线教育意味着什么？

你真正要做的不是：

> **为学习行为搭建“最低可运行环境”**

| 模板    | 技能能力   |

| 情绪支持  | 情绪能力   |
| 设备适配  | 物理机会   |

你在设计的是：

> **行为的“运行系统”**
