# 《Engaged》第6章读书笔记 + 在线教育平台应用分析
## 一、本章核心结构（行为工程视角）
### 1. 本章真正核心问题
当通过研究发现大量阻碍用户完成目标行为的能力障碍时，产品应优先选择哪些障碍进行解决，才能以有限资源实现最大的行为改变效果？

### 2. 为什么不能全部解决？
- 产品资源有限：开发、时间、人力等资源均有边界，无法支撑解决所有障碍的功能开发。
- 超出产品职责范围：部分障碍源于用户自身生活环境、固有认知等，并非产品设计所能覆盖（如用户缺乏购买专业工具的经济能力，若产品核心并非提供工具补贴，则无需介入）。
- 设计的本质是“取舍”：盲目堆叠解决所有障碍的功能，会导致产品臃肿、核心价值模糊，反而降低用户体验。

### 3. 能力障碍排序标准
| 标准 | 含义 |
| --- | --- |
| 普遍性 | 受该障碍影响的用户占比，影响多数人的障碍优先级更高 |
| 发生频率 | 障碍出现的频繁程度，频繁出现的障碍即使可克服，也会持续消耗用户耐心 |
| 影响程度 | 障碍是否直接阻断目标行为发生（完全阻断＞轻微不便） |
| 可解决性 | 该障碍是否能通过产品设计有效消除或规避 |
| 成本与资源 | 解决障碍所需的开发成本、时间成本是否在项目实际限制内 |
| 与产品边界匹配度 | 解决该障碍是否符合产品的核心定位和职责范围 |

**关键强调**：排序是行为设计中最关键的决策步骤，直接决定产品资源的投入效率和行为改变的成功率。

### 4. 评分机制（行为工程方法）
- 评分范围：每个标准按“0-3分”打分（0分=完全不相关，3分=程度最高）。
- 计算方式：为每个障碍在6个标准下分别打分后，求和得出总分。
- 筛选逻辑：按总分降序排序，选取前2-3个高分障碍（无固定数量，复杂项目可多选，小型项目聚焦1-2个）。
- 核心原则：这是基于数据和规则的工程决策，而非依赖设计师直觉，确保优先级选择的客观性。

### 5. 干预功能（Intervention Functions）
| 干预功能 | 作用 |
| --- | --- |
| 教育（Education） | 向用户提供完成目标行为所需的知识（如概念、步骤、标准） |
| 培训（Training） | 通过指导和练习，帮助用户培养完成目标行为的技能 |
| 说服（Persuasion） | 引导用户改变认知，愿意尝试或坚持目标行为 |
| 激励（Incentives） | 为用户的目标行为提供奖励或诱惑 |
| 强制（Coercion） | 对未完成目标行为或做出不当行为进行惩罚 |
| 限制（Restriction） | 通过规则或设计，增加不当行为的执行难度 |
| 赋能（Enablement） | 通过工具、规则等，降低目标行为的执行难度 |
| 环境重构（Environmental restructuring） | 改变用户的物理或社会环境，让目标行为更易发生 |
| 示范（Modeling） | 展示期望的行为模式，以榜样作用引导用户学习 |

**关键说明**：干预功能是行为改变的“解决路径类别”，并非直接可落地的产品功能，需要设计师进行转译。

### 6. 关键转换思想
设计师的核心工作是将抽象的“干预功能”转化为具体、可落地的“产品功能”，确保干预逻辑与用户体验无缝衔接。

| 干预功能 | 产品功能示例 |
| --- | --- |
| 教育 | 场景化微课程、操作步骤嵌入式提示、关键概念注解 |
| 培训 | 分阶段练习任务、错误反馈指导、技能闯关系统 |
| 赋能 | 自动计划生成器、一键跳转工具、进度追踪模板 |
| 环境重构 | 默认学习时间提醒、固定学习场景入口、干扰项隐藏设计 |
| 示范 | 优秀案例拆解、用户成功实践分享、专家操作演示 |

### 7. 本章一句话核心总结
在资源有限的前提下，行为改变产品的核心是通过科学的标准和评分机制筛选出优先级最高的能力障碍，再将匹配的干预功能精准转译为产品功能，以“少而精”的设计实现最大的行为改变效果。

## 二、在线教育虚拟案例：UI设计项目训练平台
### 产品目标
帮助用户（零基础或入门级）独立完成一个完整的UI设计项目（如移动端APP界面设计），掌握从需求分析到最终交付的全流程技能。

### 🧩 ① 已发现能力障碍清单
1. 缺乏UI设计项目的具体执行步骤指导（不知道从需求分析、原型设计到视觉落地的先后逻辑）；
2. 设计软件（如Figma）操作不熟练（基础工具使用、组件化设计等技能不足）；
3. 设计过程中没有即时反馈（不知道自己的设计是否符合规范、存在哪些问题）；
4. 时间碎片化，难以坚持完成长周期项目（无法持续投入足够时间推进项目）；
5. 不清楚作品的优劣标准（缺乏专业评价维度，无法自我校验）；
6. 缺乏同行交流支持（遇到问题无人探讨，动力易衰减）。

### 🧩 ② 建立优先级评分表
| 障碍 | 普遍性（0-3） | 发生频率（0-3） | 影响程度（0-3） | 可解决性（0-3） | 成本与资源（0-3） | 与产品边界匹配度（0-3） | 总分 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 缺乏具体执行步骤指导 | 3 | 3 | 3 | 3 | 2 | 3 | 17 |
| 设计软件操作不熟练 | 3 | 3 | 3 | 3 | 2 | 3 | 17 |
| 没有即时反馈 | 2 | 2 | 2 | 2 | 2 | 3 | 13 |
| 时间碎片化难以坚持 | 3 | 3 | 2 | 1 | 2 | 2 | 13 |
| 不清楚作品优劣标准 | 2 | 2 | 2 | 2 | 1 | 3 | 12 |
| 缺乏同行交流支持 | 2 | 1 | 1 | 1 | 2 | 2 | 9 |

### 🧩 ③ 选出前3个核心障碍及原因
最终筛选：缺乏具体执行步骤指导、设计软件操作不熟练、没有即时反馈。
- 原因1：总分最高（17分、17分、13分），覆盖了绝大多数用户（普遍性3分），且频繁出现（频率3分），直接阻断项目推进（影响程度3分），是用户完成目标行为的核心卡点；
- 原因2：可解决性强（均≥2分），且与产品“UI设计项目训练”的核心定位高度匹配（匹配度3分），属于产品职责范围内的关键障碍；
- 原因3：解决成本相对可控（成本2分），无需超出项目资源限制，能以有限投入实现显著的行为改变。

### 🧩 ④ 干预功能匹配
| 障碍 | 核心干预功能 |
| --- | --- |
| 缺乏具体执行步骤指导 | 教育（提供步骤知识）、培训（分阶段练习） |
| 设计软件操作不熟练 | 培训（技能练习）、赋能（降低操作难度） |
| 没有即时反馈 | 示范（展示正确案例）、赋能（提供自检工具） |

### 🧩 ⑤ 转化为产品功能
| 干预功能 | 平台具体功能设计 |
| --- | --- |
| 教育 | 1. 分阶段任务指南：将UI项目拆分为“需求分析→低保真原型→高保真设计→交付规范”4个阶段，每个阶段明确核心任务、输出物要求和时间建议；2. 场景化注解：在每个任务节点嵌入“为什么要做这一步”“常见误区”等知识卡片。 |
| 培训 | 1. 交互式操作教程：针对Figma核心功能（组件库创建、样式复用、原型动效）设计“边学边练”模块，用户完成操作后才能解锁下一个任务；2. 阶段闯关练习：每个项目阶段配套2-3个针对性技能练习（如“组件化设计练习”“配色规范练习”），强化实操能力。 |
| 赋能 | 1. 设计模板库：提供需求文档模板、原型组件库、交付规范模板，用户可直接复用修改，减少重复工作；2. 即时自检工具：内置设计规范检测器（如字体一致性、间距规范、配色合规性），用户提交设计后自动生成问题清单和修改建议；3. 软件操作快捷键悬浮窗：在用户操作软件时，实时显示当前场景下的常用快捷键和操作技巧。 |
| 示范 | 1. 优秀案例拆解：每个阶段展示3-5个优秀示例，标注“亮点设计”“符合规范的细节”；2. 错误案例对比：呈现常见错误设计与正确设计的对比，帮助用户快速识别问题。 |

## 三、最终启发
本章对教育产品最大的启发是：教育产品的行为改变设计不在于“覆盖所有用户痛点”，而在于“聚焦核心能力障碍”，以科学的优先级排序锁定关键卡点，再将抽象的干预功能精准转译为贴合用户学习场景的产品功能，用有限资源实现高效的技能提升和行为坚持。
