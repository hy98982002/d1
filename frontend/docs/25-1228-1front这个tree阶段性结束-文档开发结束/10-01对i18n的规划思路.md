## 五、为什么 i18n 必须晚于 SPA → SSG

### 1️⃣ SSG 会直接改变「文本生成方式」

在 SPA 阶段：

* 文本 = 运行时渲染
* i18n = 纯前端问题

在 **SSG / Hybrid 阶段**：

* 文本 = 构建期生成 + 运行时补充
* i18n = **构建系统级问题**

如果你现在就写 i18n：

* 你一定会在 SSG 时 **推翻一半设计**
* 包括：

  * 路由结构
  * 默认语言策略
  * hreflang
  * sitemap 拆分
  * canonical 规则

👉 **这是典型的“顺序错误型返工”**

---

### 2️⃣ i18n 和 SEO / AEO 强耦合

你自己其实已经隐约意识到了这一点：

* 多语言 ≠ UI 文案切换
* 多语言 =

  * URL 结构
  * 搜索引擎索引策略
  * hreflang / canonical
  * 百度 / 必应 / Google 行为差异

而这些：

> **全部依赖最终的 SSG 架构**

---

## 六、那现在“什么都不做”是不是不专业？

不是。

你现在应该做的是 **“文档冻结 + 代码不动”**。

### 正确状态应该是：

* ❌ 不引入 `vue-i18n`
* ❌ 不写语言包
* ❌ 不抽象 `$t()`
* ❌ 不做 LanguageSwitcher
* ✅ **在文档中明确：i18n 是计划内能力，但未进入实现阶段**

---

## 七、i18n 在文档中的“正确表达方式”（关键）

### 应该怎么写（结构层面）

在 `AI_EXECUTION_CONTEXT.md` 中，和 RBAC / PWA 同级，新增一小节，例如：

```
### i18n（多语言）能力规划状态
```

### 这段必须表达清楚 4 件事（缺一不可）

1. **当前状态**

   * 国内版仅简体中文
   * 海外版未上线
2. **当前决策**

   * 暂不引入 i18n 框架
3. **原因**

   * 架构仍在 SPA → SSG 迁移中
   * 多语言依赖最终 URL / SSG 策略
4. **触发条件**

   * SSG 稳定
   * 海外站点规划明确
   * SEO / hreflang 策略确定

这和你 RBAC / PWA 的写法形成**完全一致的“工程记忆模式”**。
