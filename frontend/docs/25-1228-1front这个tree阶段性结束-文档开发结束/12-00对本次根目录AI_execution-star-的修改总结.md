## 三、现在这版中 **必须修正的 3 个问题**（重点）

---

### ❌ 问题 1：`rbac.ts` 指令文件与“禁止 RBAC”存在语义冲突

你在 **5.5 RBAC 使用判断**里写得非常清楚：

> 当前阶段禁止引入完整 RBAC 体系

但在目录结构中你仍然写了：

```
directives/
└── rbac.ts                  # 权限控制指令 (v-permission, v-role)
```

#### 为什么这是问题？

对 AI 来说，这是**强冲突信号**：

* 文档说：禁止 RBAC
* 代码说：这里有 rbac.ts + v-role

AI 很容易得出错误结论：

> “RBAC 已经部分存在，可以继续扩展”

#### 你有两个**必须二选一**的修正方案：

**方案 A（推荐）｜改名降级语义**

```ts
directives/
└── accessGuard.ts   // 基于用户状态的访问控制指令（非 RBAC）
```

并在文档中明确一句：

> 该指令不实现角色-权限映射，仅用于 UI 级访问保护

**方案 B（保守）｜保留文件但强声明**
在 5.5 RBAC 章节补一句：

> 当前 `rbac.ts` 文件仅为历史命名遗留，
> 实际实现不构成 RBAC 体系，禁止在其上扩展角色模型。

👉 **不选其一，这里一定会出事故。**

---

### ❌ 问题 2：Accessibility 章节的“Current implementation”用词过强

你在第 8 章大量使用了：

> Currently implemented to comply with WCAG 2.1 AA standards

这是**危险表述**。

#### 为什么？

* WCAG 2.1 AA 是**可审计标准**
* 你现在没有自动化审计、没有声明测试范围
* 对 AI 来说，这句话 = **“已完全合规”**

#### 建议修改为（非常重要）：

把所有 **“to comply with”** 改为：

> **“implemented with the intent to align with WCAG 2.1 AA principles”**
> 或
> **“implements key WCAG 2.1 AA practices where applicable”**

👉 否则未来任何无障碍缺陷，都会变成“违宪级冲突”。

---

### ❌ 问题 3：`TeacherCard.vue` 容易被 AI 误判为“教师体系入口”

你在 16.3 已经解释得很清楚了，但**位置太靠后**。

#### 风险点在于：

* AI 往往只扫目录
* 看到 `TeacherCard.vue`
* 很容易联想到“教师端 / 教师体系”

#### 建议的低成本修复：

在 **第 3 节 components 列表中**，直接改注释：

```vue
TeacherCard.vue  # Static instructor profile display (NOT a teacher system)
```

并在 2. 项目背景或 5.x 中补一句总原则：

> 平台当前不存在“教师作为系统角色”的概念，
> 所有讲师信息仅作为内容元数据展示。
